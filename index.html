The car has no encoders, so its position is estimated by dead reckoning from the commanded wheel speeds. That drifts with wheel slip and battery level: treat it as a rough guide, not a precise position. A proportional heading controller steers; the car stops within 25 mm of the estimate.

Line follow

Left sensor Right sensor
Status: idle

Line following runs on the Quarky itself, so it keeps working at full speed whatever the USB link does. The page must keep pinging: if it goes quiet for 2 s the car stops.

Line follow settings

Two digital sensors give three cases: line on the left → steer left, on the right → steer right, both or centred → straight. A higher Kp steers harder. The sensor pins are set in the firmware (IR_LEFT_PIN, IR_RIGHT_PIN); find them with the IR sensor finder firmware in the Flash tab.

Car geometry (inverse kinematics)

left = v − w·T/2   right = v + w·T/2
v = forward speed %, w = turn rate % (positive = turn left), T = track width. 1 % of w moves each wheel 1 % per 50 mm of half-track (so a wider car needs a bigger wheel difference for the same w). If a wheel would pass 100 %, both are scaled by the same factor. Track width and wheel diameter also size the car on the map and set the dead-reckoning distances.

Wiring corrections

If the car turns the wrong way or a wheel spins backwards, fix it here. Swap is applied first, then the inversions. These are sent to the car, so line follow uses them too.

Simulator

The motor code reused from the Quarky library drives each motor with one PWM pin, so without direction pins the car cannot reverse: negative wheel speeds are limited to 0. The Simulator behaves like that unless you tick the box. When connected, the real car reports what it can do.

Flash from the browser

  1. Choose the port and detect the chip
    Closes the control connection first and stops the motors. Pick the Quarky's port in the browser's window.
  2. Write the firmware
    Verifies the SHA-256 of the file against the manifest, writes it, checks the written data, then hard-resets the board.
    Leave this unticked unless the board misbehaves after a normal flash. Erasing the whole flash also deletes everything else stored on the Quarky (saved settings, Wi-Fi data, any other program).
  3. Reconnect
    After the reset the page reopens the control connection by itself and waits for the car to say hello.

Troubleshooting

The chip isn't detected / "Failed to connect" (auto-reset doesn't work)
  1. Unplug the USB cable, then hold the board's BOOT (also called IO0 / FLASH) button, plug the cable in, and keep holding for about 2 seconds.
  2. Or, with the cable plugged in: hold BOOT, tap RST / EN (reset) once, then release BOOT.
  3. Click Choose port & detect chip again while the board is in this state. After flashing, press RST / EN (or unplug and replug) if the page doesn't restart the board by itself.
  4. If your Quarky has no BOOT button, try a different USB cable (some are power-only) and a lower speed (115200).
The port is busy / can't be opened
  • Only one program can use a serial port at a time. Close the Arduino IDE (and its Serial Monitor), PictoBlox / mBlock, Thonny, PuTTY, and other browser tabs using this page or any serial site. This page closes its own control connection before flashing.
  • Unplug and replug the cable, then pick the port again.
  • Linux: you may need to be in the dialout group (sudo usermod -aG dialout $USER, then log out and in). Windows: check Device Manager for the COM port and install the CH340 / CP210x driver if it's missing.
A flash failed or stopped half-way
  • Don't unplug it: just run the flash again. An interrupted write leaves the old or half-written program, but the chip's built-in bootloader still works, so it can always be flashed again.
  • Try the 115200 speed, a shorter or better USB cable, and a USB port directly on the computer (not a hub).
  • If it still fails or the board doesn't start afterwards, put it in the bootloader manually (see the first item), tick Erase all flash first and flash again.
  • If the hash check fails, the firmware file was damaged or changed: reload the page (Ctrl+F5) so it fetches the file and manifest again.
After flashing, the page can't talk to the car
  • Wait a few seconds: the Quarky restarts when its port is opened. Use Reconnect in the header.
  • Check that the console shows a hello message from steam-car. If you flashed the IR sensor finder, it prints sensor readings instead and doesn't answer the car page: flash the car firmware again.
